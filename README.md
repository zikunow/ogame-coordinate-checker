# Координаты — OGame RU

Открытый инструмент для сравнения координат планет между русскими вселенными OGame.
Выберите свою вселенную, найдите игрока по нику или ID и проверьте занятость всех его планет в выбранных вселенных.

**Сайт:** https://zikunow.github.io/ogame-coordinate-checker/

## Что показывает

- Поиск по нику, части ника и точному ID; одинаковые ники различаются по ID.
- Все планеты выбранного игрока, без лун.
- Владельца и статус на тех же координатах в других RU-вселенных.
- Второй столбец со сводкой: активные, неактивные, РО, неизвестные и прочие статусы.
- Своя вселенная исключается автоматически. Доступны только RU-вселенные от Capella до Imai включительно. Вселенная 1 и вселенные после Imai не включены в базу и списки выбора.
- Даты снимков, прямые ссылки на API, CSV-экспорт и ссылка на готовую проверку.
- Адаптивная таблица: координаты и сводка закреплены при горизонтальной прокрутке.

## Как работает база

`scripts/update_data.py` использует только стандартную библиотеку Python и официальные публичные источники:

- https://lobby.ogame.gameforge.com/api/servers — список серверов, только открытые RU-вселенные с номерами 103–264 (Capella–Imai включительно);
- `https://s{number}-ru.ogame.gameforge.com/api/serverData.xml` — настройки и размеры;
- `https://s{number}-ru.ogame.gameforge.com/api/players.xml` — ники, ID и статусы;
- `https://s{number}-ru.ogame.gameforge.com/api/universe.xml` — планеты и владельцы.

Документация API: https://forum.origin.ogame.gameforge.com/forum/thread/44-ogame-api/

Для каждой вселенной создаётся `site/data/ru-{number}.json`. В `manifest.json` хранится список вселенных, количество записей и оригинальные timestamps API. Браузер загружает JSON с того же сайта; игровой аккаунт, API-ключи и доступ к Gameforge из браузера не нужны.

GitHub Actions запускается при изменении кода, вручную и каждые 6 часов (UTC, на 19-й минуте). Workflow скачивает API, проверяет данные, коммитит JSON и публикует каталог `site/` в GitHub Pages. Плановые запуски GitHub могут задерживаться; в неактивных публичных репозиториях GitHub может отключить расписание.

При ошибке одного API сохраняется предыдущий снимок с отметкой `stale`. Если сохранённого снимка нет, вселенная помечается `unavailable`. Ошибка загрузки никогда не превращается в «свободно». Если все API недоступны, обновление завершается ошибкой и сохраняется прежний опубликованный сайт.

## Значение статусов и ограничения

| Код | Статус | Группа в сводке |
| --- | --- | --- |
| Нет кода | Без особых отметок API, не обязательно онлайн | Активные |
| `i` / `I` | Неактивность ≥7 / ≥28 дней | Неактивные, если нет `v` |
| `v`, `vi`, `vI` | Режим отпуска, возможно с неактивностью | РО |
| `b`, `o`, `a` | Бан, вне закона, администратор | Прочие, если нет РО/неактивности |
| Владелец отсутствует | Планета есть в карте, но ID нет в players.xml | Неизвестные |

Группы не пересекаются: приоритет РО → неактивность → обычный/другой статус. Считаются позиции в разных вселенных, а не уникальные люди. Даже одинаковые ники на разных серверах не доказывают, что это один человек.

Карта API обычно обновляется раз в неделю, players.xml — раз в сутки. Запуск нашего сборщика чаще не делает сам API свежее. «Свободно» означает отсутствие планеты **на дату карты**. Новые планеты и переселения после этой даты могут не попасть в результат. Если игрок есть в players.xml, но в карте нет его планет, сайт сообщает об этом. Некоторые API содержат административные планеты за пределами обычных галактик: существующие записи сохраняются.

JSON — текущий снимок. Git хранит историю изменений; никакой приватной информации, шпионских отчётов, игровых cookies или токенов проект не собирает. API-данные принадлежат их поставщику; лицензия MIT относится к коду инструмента. Проект не связан с Gameforge.

## Локальный запуск

Требуются Python 3.10+ и Node.js 22+ для тестов. Устанавливать зависимости не нужно.

```sh
python scripts/update_data.py
npm run check
npm test
python -m unittest discover -s tests -p 'test_*.py'
python -m http.server 8000 --directory site
```

Откройте http://localhost:8000. Сайт нужно запускать через HTTP, а не через `file://`.

## Публикация своего форка

1. Создайте публичный fork.
2. В Settings → Pages → Build and deployment выберите **GitHub Actions**.
3. Разрешите workflow записывать `contents` в репозиторий (это уже запрошено в YAML).
4. Запустите **Update API snapshots and deploy Pages** через Actions → Run workflow.
5. При необходимости замените ссылку на репозиторий в `site/index.html` и ссылку на сайт в README.

Файлы сайта используют относительные пути и работают в подкаталоге GitHub Pages без сборщика.
